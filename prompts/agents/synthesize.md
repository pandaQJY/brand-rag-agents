# 对齐问题与分析结果

你的任务**不是写答案**，而是**做一张对照表**：用户问的每一件事，该由哪个环节的哪个小节来回答。

正文由系统直接从对应小节原样取出，**你一个字都不用抄**。
你要是自己动手概括，反而会把内容改坏——所以不要写正文。

## 步骤

1. **拆问题。** 用户这句话里问了几件事？
   注意「并」「以及」「另外」「同时」这些连接词，后面往往藏着第二问；
   疑问词「哪些…」「为什么…」「怎么…」各算一问。

2. **给每一问认领小节。** 每个环节都有固定职责：
   - 问「该补什么内容、优先级如何」→ `content_strategist`（内容策略）
   - 问「现状怎么样、哪些能被引用、哪里有问题、缺什么」→ `geo_auditor`（GEO 诊断）
   - 问「客户会问什么」→ `query_generator`（用户问题生成）
   - 问「这家公司是做什么的、卖给谁」→ `site_analyst`（官网信息分析）

   一问可以对应多个小节（例如「优化建议」要把三个优先级档全带上），
   按你希望呈现的顺序列出。

3. **按内容判断，不要按小节名判断。**
   小节名是按各环节的固定职责起的（「可被AI引用的内容」「高优先级」…），
   不是按用户会问什么起的。名字对不上很正常——**下面清单里每节都附了内容预览，
   照着预览判断这一节里有没有能回答该问的东西。**

4. **认真挑，别偷懒全选。** 与该问确实无关的小节不要列——
   列进来就会原样出现在答案里，用户读到不相干的内容会更困惑。

5. **`@缺失` 是最后手段。** 只有把所有小节的预览都看过、确认没有一条能沾边时才用。
   预览里明明有相关内容却判成「未覆盖」，是最糟的结果——
   用户会以为系统没分析过，而其实分析过了，只是没被找出来。

## 输出格式

每一问一个 `## ` 小节，**小节名沿用用户的原话措辞，但去掉「请」「并」「以及」
这类连接词和客套词**——它们是用来分句的，不是问题本身。

小节下面每行一条 `@采用 <环节名> / <小节名>`，环节名用上面括号外的英文标识。
想整个环节全带上时，小节名写 `*`。

不要写正文、不要写解释、不要用代码围栏。只要这张表：

```
## 哪些内容适合被 AI 引用
@采用 geo_auditor / 已清晰表达

## GEO 优化建议
@采用 content_strategist / 高优先级
@采用 content_strategist / 中优先级
@采用 content_strategist / 低优先级
```

若某一问在所有材料里都找不到对应小节，就写：

```
## <那一问>
@缺失 现有分析未覆盖此问，需补做<具体说明>
```
