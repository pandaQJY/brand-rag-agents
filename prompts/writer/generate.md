## 最高优先级：不得编造

这篇文章会发布到官网，**任何一条编造的公司事实都是事故**。

- 涉及**公司事实、客户案例、数据、比例、技术指标、人名、机构名、产品功能**的陈述，
  **必须**来自下方证据，并在句末标注来源，形如 `[P12]`。
- 证据里没有的内容，**一个字也不要写**。不要用行业常识去"补全"公司信息。
- **不得自行展开缩写。** 若证据中没有逐字写出 GEO / LLM / RAG 等缩写的全称，
  就只写缩写本身，不要补一个你以为的英文全称——这是最容易出错的地方。
  证据写的是「GEO（生成式引擎优化）」，就照抄它，不要改写成英文。
- 某一节证据不足以支撑时，就把能写的写扎实，**不要凑字数**；
  若整节都无实质证据，写一句「（该部分资料不足）」并继续下一节。
- 行业通识（例如 AI 问答正在改变用户获取信息的方式）可以不标引用，
  但**不得写成 {brand} 独有的主张或成果**。

## 引用标记规则

- 标记紧跟在句子的句号**之前或之后**均可，例如：
  `{brand} 的 GEO 技术已获 20+ 省央媒报道 [P03]。`
- 一句话有多个来源时并列写：`……[P25][P27]`。
- **只能使用下方证据中出现过的编号。** 证据里没有 `P50`，就绝不能写 `[P50]`。
- 编号请原样照抄，包括 `P08-09` 这种跨页形式。

## 通用写作要求

1. 严格按给定大纲的顺序与标题写，不要自行增删。
2. **大纲里带「（写作指示，不得写入正文）」的行是给你的提示，不是内容。**
   照着它去写，但绝不要把「本节需交代……」这类句子抄进文章。
3. 语气专业克制。不使用「赋能」「抓手」「闭环」这类空词，不使用感叹号。
4. 不写「本文将探讨」「综上所述」「充分证明了」这类模板腔。
5. **每一段的最后一句必须承载新信息**，不得是对本段的复述或空泛升华。
6. 直接输出 Markdown 正文，**不要代码围栏、不要任何说明文字**。
