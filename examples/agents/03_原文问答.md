# 示例三：原文问答（检索型问题）

这一例展示的是**分析型 Agent 结构上答不了的一类问题**。

四个分析型 Agent 都是「通读全站 → 输出固定小节」的形态。问「GEO 和 SEO 有什么区别」时，
它们的固定小节里没有一节承担「官网对某个概念是怎么讲的」——
**答案就在已抓取的页面里，分析这条路却取不出它**。

这类问题需要的是检索。把混合检索指向站点语料，路径即成立：
检索定位到具体小节 → 模型据此作答 → 标注页面 URL 供人点开核对。

## 输入

```
python -m apps.cli "GEO 和 SEO 有什么区别"
```

## 看点

| 环节 | 说明 |
|---|---|
| **路由落点** | 「区别」命中 `site_qa` 而非 `site_analyst`——问「官网怎么讲」与问「这家公司什么样」是两类需求，不该落到同一个 Agent |
| 检索粒度 | 站点语料按 h2 分节切分，因此命中的是《六、结语》《二、GEO：不是SEO升级…》这类**小节**，而不是一整页 |
| 引用锚点是 URL | 知识库锚页码 `[P29]`，站点锚 URL——两份语料各建索引，正是为了让证据分得清出处 |
| 两节分工 | 「回答」是归拢后的综述，「官网原话」是带「」的逐字引用，保留了综述压掉的细节（Product-centric / PageRank→RAG） |
| 单环节也要收口 | 原文问答固定输出三节，而用户只问区别——收口环节挑出「回答」那节，不把三节整份倒给用户 |

## 回答
SEO主要解决网站在传统搜索结果中的排名问题，而GEO关注品牌信息是否能够被生成式AI理解，并在AI回答场景中获得展示机会。两者并不是替代关系，而是企业数字信息可见性的不同组成部分。SEO优化的是“关键词排名”，目标是网页列表；GEO优化的是AI的“意图匹配”，目标是成为AI生成的“唯一答案”或“精选建议”。SEO以产品为中心，侧重链接权重；GEO以用户为中心，核心是理解用户痛点并提供解决方案。[来源: https://www.wanxitech.cn/blog/why-ai-cant-find-your-content-manufacturing-geo-case, https://www.wanxitech.cn/blog/qianwen-direct-order-omnichannel-scraping-taobao-search-rethink]

## 官网原话
「SEO主要解决网站在传统搜索结果中的排名问题，而GEO关注品牌信息是否能够被生成式AI理解，并在AI回答场景中获得展示机会。两者并不是替代关系，而是企业数字信息可见性的不同组成部分。」[来源: https://www.wanxitech.cn/blog/why-ai-cant-find-your-content-manufacturing-geo-case]
「目标不同：SEO优化的是“关键词排名”，目标是网页列表；GEO优化的是AI的“意图匹配”，目标是成为AI生成的“唯一答案”或“精选建议”。逻辑不同：SEO以产品为中心（Product-centric），侧重链接权重；GEO以用户为中心（User-centric），核心是理解用户痛点并提供解决方案，其底层逻辑已从PageRank算法转向了基于大语言模型（LLM）的检索增强生成（RAG）机制。」[来源: https://www.wanxitech.cn/blog/qianwen-direct-order-omnichannel-scraping-taobao-search-rethink]
